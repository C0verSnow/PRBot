## 边界与保留行为

- code 表示 Codex 的报告，并非控制器独立审查代码正确性；PR、Issue、CI 来自 GitHub 读取结果。
- CI 是任务结束时对已记录 head_sha 的快照，不做持续后台重验。已保存的旧结果不自动重写，旧目录和文件不删除。
- SDK 返回 failed 但带有效 PR 时仍核对 GitHub 成果；不擅自把未确认的代码工作宣称完成。needs_clarification 不当成交付。
- PR 不存在或无法读取时展示未验证，不宣称成功；跨仓库或错误 PR 编号仍明确失败，并保留报告供排查。
- 保留原必需检查配置 PRBOT_REQUIRED_CHECKS（默认 test,dmg）；没有检查结果或没有配置必需检查均不算通过。不绕过检查、不自动关闭 Issue、不批准、不合并 PR。
- 新目录只影响后续接收的任务；已接收任务沿用保存的 workspace_root 和 configuration_file。旧配置复制仅发生在用户重新选择目录或打开配置目录时，而且目标尚不存在；环境变量优先级不变。
- WebKit 的延迟提交/错误/交付结果使用受控响应；真正的后端读写、归档与 GitHub 状态组合由 Python 回归测试覆盖。不是新一轮真实 Codex、Infisical、Redis 和 GitHub 写入验收。
