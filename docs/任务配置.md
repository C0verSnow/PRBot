# 仓库任务配置和运行边界

## 首次配置

在 PRBot 原生界面选择“配置任务”。GitHub Token 需要 Contents、Pull requests、Issues 读写，以及 Checks、Commit statuses 和 Actions 读取权限；组织仓库还需对应组织授权。启动 API 校验只能确认仓库可写和读取能力，GitHub 不提供通用接口证明细粒度 Token 的全部写权限，PR/Issue 操作仍可能被拒绝，届时记录实际失败。

Codex 认证沿用本机已登录的 ChatGPT/Plus：将 `~/.codex/auth.json` 的登录内容导入 macOS 钥匙串 `org.prbot.execution / codex-login`。不会导入 Codex 配置、历史、连接器或其他目录。登录文件须为 600 权限。若登录保存在其他钥匙串中而没有 auth.json，需要先通过 Codex 生成可导入登录；当前界面不支持读取其他应用的钥匙串登录。登录刷新在每次执行的受保护临时目录中进行，完成后回存 PRBot 钥匙串，不会回写原 Codex 登录；过期后重新导入。

GitHub Token 存在 `org.prbot.execution / GITHUB_TOKEN`。开发环境可以用 `GITHUB_TOKEN` 环境变量覆盖；不要写入 config.json。Telegram Token 继续沿用既有配置。应用不自动读取项目 `.env`，防止把目标仓库提供的环境变量当成宿主执行凭据。

高级部署可调用应用可执行文件的 `configure-tasks` 命令，从标准输入读取 JSON：
`github_token`、`users`（逗号分隔字符串）、`repos`（逗号分隔字符串），可选 `telegram_token`、`work_root`（已存在且可写的父文件夹绝对路径）。
请通过受保护的凭据管理脚本直接写入 stdin，勿把密钥放在命令行参数、聊天或仓库文件中。
此命令与原生界面使用相同的钥匙串和配置逻辑。

## 非秘密设置

文件位置：`~/Library/Application Support/PRBot/config.json`，文件权限 600。

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| PRBOT_ALLOWED_USERS | 空 | 逗号分隔的数字用户 ID；空时不启用任务 |
| PRBOT_ALLOWED_REPOS | 空 | 逗号分隔的 owner/repo；空时不启用任务 |
| PRBOT_SESSION_TTL | 900 | 输入等待有效期，秒 |
| PRBOT_TASK_TIMEOUT | 1800 | 每次 SDK 执行或独立审核超时，秒 |
| PRBOT_TASK_CONCURRENCY | 1 | 同时执行上限，1–4 |
| PRBOT_CI_TIMEOUT | 3600 | 每轮远端检查等待秒数；超时报告 validating 并继续等 |
| PRBOT_REQUIRED_CHECKS | test,dmg | 必须成功的 GitHub 检查名称；其他仓库按其 CI 配置 |
| PRBOT_WORK_ROOT | 应用数据目录 | 用户通过“选择工作路径”选中的统一父目录，新任务位于其中 PRBot-workspaces/编号 |
| PRBOT_LOCAL_REPOS | {} | JSON 对象：owner/repo 对应已有本地仓库绝对路径 |

示例允许用户为 `6190688941`，仓库为 `c0versnow/prbot`。设置通过应用或手动编辑文件后重启生效。

优先从配置的本地仓库复制已提交对象，再从 origin 同步默认分支；不修改原工作区，不带入其未提交文件。不配置本地路径时直接 clone。默认工作区位于数据目录下 `workspaces/任务编号`；选择工作路径后，新任务使用 `所选目录/PRBot-workspaces/任务编号`，保留供排查，不自动清理。切换路径不会移动已有任务；任务库继续保存在应用数据目录中。

## 执行与验证

固定依赖：`openai-codex==0.163.0`，匹配 `openai-codex-cli-bin==0.163.0`。PyPI 发布元数据指向 OpenAI 官方 codex 仓库，要求 Python >=3.10；本项目固定 Python 3.12。实际 wheel 导出 `Codex`、`CodexConfig`、`Sandbox.read_only`、`ApprovalMode.deny_all`，通过 app-server stdio 运行，无需 Node。发布包含 macOS 11+ arm64 runtime wheel，最终兼容性以 macOS 14 远端 CI 和设备验收为准。

来源：[PyPI SDK](https://pypi.org/project/openai-codex/0.163.0/)、[匹配 runtime](https://pypi.org/project/openai-codex-cli-bin/0.163.0/)、[官方 SDK 代码](https://github.com/openai/codex/tree/main/sdk/python)、[官方文档](https://developers.openai.com/codex/sdk)。接口以下载的 0.163.0 wheel 为准，不能仅依赖会变化的 main 文档。

SDK 在清理环境的子进程中运行，使用独立临时 Codex home。临时认证文件为 600 权限，退出删除，常驻存储为钥匙串。不会向 SDK 提供 GitHub/Telegram Token。外层 macOS Seatbelt 只允许原生 Codex runtime 执行，不允许启动 shell、Python 或构建工具；SDK 使用只读模式和拒绝审批，禁用 shell、网页和应用连接器。模型仅根据文本快照返回 JSON 文件替换方案；控制器负责实际落盘。支持最多 100 个文本文件、每个源文件小于 100KB、快照总计小于 1MB，超过范围明确失败。当前不支持二进制编辑。禁止越界路径、隐藏凭据文件、符号链接逃逸及凭据格式差异；`.github` 和 `.gitignore` 可参与任务。

控制器检查实际 Git 差异和文档更新、单独调用 SDK 做需求覆盖审核（审核结果不等于运行测试），然后提交并推送草稿 PR。`test.md / test done` 示例另做精确内容检查。所有运行验证在远端 CI，缺失的检查不会当作成功。目标仓库必须有与设置匹配的远端检查；没有时保持等待。

## 恢复和失败

会话、任务、回复分别保存在与 Telegram Token 隔离的既有 SQLite 数据库中，迁移仅增加表和索引。同一 update 和活动任务原子去重；发送失败只重试已保存回复，最多 5 次，超过预算保留 exhausted 状态供管理员检查。Telegram 请求超时可能已送达，因此不承诺绝对不重复通知。

停止服务会终止 SDK 进程组、取消工作器并标记 interrupted。重启时对已记录提交的任务查询远端 PR，保存能确认的链接，将曾在执行中的任务标记 interrupted，不自动重跑。请人工核对工作区和远端分支，再提交新任务。推送结果不明确时比对远端 SHA；PR 创建结果不明确时先按唯一 feature 分支查找；Issue 关闭不明确时先读取其状态。PR 创建、待审、Issue 关闭、合并分别报告。

任务模型保留 source.kind/source.number 与 context，可扩展到 PR；不为普通仓库任务补建 Issue。默认不合并 PR，不改默认分支。

Git 操作使用 macOS `/usr/bin/git`；目标机器需具备 Apple Command Line Tools 提供的 Git。本次目标设备已具备，Git 的缺失或失败会停止交付并给出排查提示，不会自动安装工具或修改 PATH。

macOS SDK 需要读取 `com.openai.codex` 的受管偏好来遵守管理员要求；沙箱仅放行此偏好域与系统偏好目录，不放行其他用户文件。远端检查会创建无付费 turn 的只读线程，覆盖完整配置加载。


## 工作目录 .env

选择工作路径时自动准备 `PRBot-workspaces/.env.example` 和 `.env`（权限 600），
填写后重启读取；菜单“打开配置目录”直接定位文件。模板随软件和 DMG 分发。
源码仓库也保留 `.env.example`；不会搜索或读取每个任务克隆中的 `.env`。
优先级：进程环境变量 > 当前工作目录 `.env` > `config.json` / 钥匙串 > 默认值。
空值表示回退。工作路径在软件菜单选择，避免 `.env` 自己改变自己的读取位置。
GitHub / Telegram Token 可放 `.env`；Codex 登录仍须显式导入钥匙串。
换路径不会迁移旧配置；不会覆盖用户已有 `.env`，不会将其提交到 Git。
