## Spec

确认并修复四处问题（第四处由收尾时真实 GitHub API 返回复现）：

| 触发条件 | 原行为和影响 | 修复与远端回归 |
| --- | --- | --- |
| 历史消息 sequence 为有限但超出 Date 范围的值，例如 ±1e20 | Number.isFinite 检查通过，toISOString 抛 RangeError，整个 React 页面可能白屏 | 检查 Date.getTime() 是否有效；无效时显示 Time unavailable，不伪造日期、不隐藏正文；WebKit 加两条异常历史消息并验证内容仍可访问 |
| 点击 Fetch Codex ID Token，回包 applied:false | App 仍发送 models，破坏 Fetch 只读、不启动 SDK 的既有行为 | 仅 applied:true 时自动刷新模型；WebKit 在真实 Fetch / Use token 路径统计 models 请求，验证两次 Fetch 均不增加查询、两次应用各增加一次 |
| SDK 或归档生成 interaction 追问事件 | TaskFeed 把它标成 System，同一追问在最终和历史卡片却标成 Codex | text / interaction 均属于 Codex，progress / status 仍属于 System；WebKit 同时检查追问和状态事件的角色 |
| 同一提交的 push 运行被新 PR 运行替代并取消，两套 test 仍出现在 latest check-runs 中 | 交付检查器把 cancelled 和 success 一起合并，成功 PR 被误报为 CI 失败 | 只忽略能通过 workflow、完整 SHA、分支、来源仓库、递增 run_number、suite 与同名成功检查证明已被替代的旧取消项；真正失败、其他 workflow、status 失败及缺少元数据均继续拦截 |

模型参数贯通、默认兼容、受理后的模型固定、重试和澄清传递未发现新的明确缺口。未确认存在模型改选后的重复草稿，不据此修改。没有确认的无关功能扩张。
